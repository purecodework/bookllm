# 纸面 UI 改造验证记录

## 2026-10-10 翻译准备与模型容量修正

本轮处理完整请求预算、局部结构误判、微小分块及小说精修上下文四项问题。只修改 iOS 与 TranslationCore；云端协议、计费策略、购买入口、用户数据和旧请求身份保留。未提交或推送。

| 问题 | 本轮实现与边界 |
| --- | --- |
| 自带 API 模型容量 | 新增可保存的上下文窗口／最大输出 tokens。发送前估算实际 system/user 完整消息，包含提示词、相关译名、原文、译稿、反馈与背景，并预留输出和 tokenizer 余量。自动收缩可选章级／邻近背景，限制输出预算；明确的容量拒绝最多重试两次，并在已完成预检收缩的基础上继续缩小实际 payload。必需内容仍过大时在派发前失败，不截正文、初稿、冻结译名或当前块反馈。 |
| 局部结构与文类 | 明确小说章节优先于单个表格／代码示例；局部结构保护独立于整本书文类。Chapter I／II 小说保留两章与表格。明确技术标题、论文／剧本／诗集证据仍保留原优先级。 |
| 分块边界 | 论文编号节需章节语义或布局证据，Install／Run 步骤留在所属章节；短标题随首段；Dr.、姓名首字母、常见缩写与小数不误作句末。原文逐字节保持，已能放入预算的表格／代码不再被相邻长正文拆开。 |
| 小说精修 | 新任务首译和后续阶段复用 FictionContext 的开篇风格、章名、同章邻近片段及上一章完成译稿。章级参考不重复当前块原文、初稿与当前完整反馈；新自带 API 请求的段落 IDs 引用已有 source，消除第二份完整 sourceUnits 文本。 |
| 旧任务与恢复 | 新本地 preparationVersion 与既有 pipelineVersion 分开，云端派发清除此本地元数据。旧记录缺失该版本时使用冻结的 LegacyChunker 和原精修组装；运行／完成／已准备术语的任务不升级。只有完全未开始的草稿可升级并重算自动文类，用户手选文类保留。阅读、导出、术语与修复使用同一版本的边界。 |
