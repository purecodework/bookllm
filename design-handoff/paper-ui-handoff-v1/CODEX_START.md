# Codex 实施任务：只替换最新 UI，保留现有功能

你正在一个**已具备实际功能的 iOS 小说与文档翻译 App 仓库**中工作。本任务不是从零搭建产品。请按此交接包完成 UI 接入。

## 开始前

1. 遵守仓库已有的 AGENTS/贡献规则。先查看当前技术栈、导航、设计系统、状态管理、文稿/章节模型、翻译事件订阅、文件入口、阅读器和购买入口；不得凭本原型选 React、SwiftUI 或 WebView。
2. 按顺序阅读本包 `docs/01-final-decisions.md`、`docs/02-ui-spec.md`、`docs/03-motion.md`、`docs/04-integration.md`。查看 `gallery.html` 和对应 `references/` 图，再读取 `design/tokens.json`、素材清单。
3. 输出一个短映射：现有页面/组件 → 交接包屏幕 ID；现有业务接口/事件 → UI 动作/状态。指出真正缺失的接口；没有阻塞时继续实现，不要求用户重新决定已定稿的视觉。

## 实施目标

- 保留现有引擎、API、OCR、计费、导出、登录、交易、持久化、离线能力与权限校验。
- 默认首页改为书库。翻译进度嵌在本书行内；删除独立“任务”导航入口，但不删除任务服务。
- 使用暖白细纸纹、暖墨色正文、少量墨绿，宋体阅读与系统无衬线控件；采用 tokens，不能只改背景颜色。
- 质量选择保留速读/精译/深校/精修。使用本包最后一版四张画像，主编叼烟斗；档位变化时新增角色显现、已有角色移位，不能循环晃动或冒烟。
- 精修真实呈现校对与语言专家并行，再主编整合；完整性检查不是第五个角色。
- 去掉图片/相机导入入口；保留文档导入、粘贴文本、扫描 PDF 识别核对和已有封面提取。
- 新任务不要求术语人工确认，不展示三个术语模式。使用已有自动维护路径。
- 每本书的 `··· → 译名` 是可选工具。只展示原词与译名；修改面板包含一个译名字段、可展开语境、取消/保存。保存不触发模型，不重译、不扣点、不改已完成章节。
- 如果现有后端只支持整表人工 gate、全局重译或不支持“未来内容生效”的译名覆盖，请列为接入缺口。不要为了假装 UI 可用而伪造完成、清空旧任务、自动扣费或偷偷改 pipeline。

## 建议实施顺序

**第一步：视觉基础与主路径。** 接入 tokens、纸纹和角色；实现书库行、状态筛选、进度面板、书目菜单与正确返回；绑定真实 store，不制造第二套数据源。

**第二步：质量与阅读。** 接上既有质量/风格/目标语言设置、四档动效、原文/译文/对照、目录、字号和阅读锚点；保留所有既有结构保护与流式阅读限制。

**第三步：简化译名与其余入口。** 使用已存在的自动术语维护服务；实现可选译名编辑；统一导入/OCR/导出/账户/API/购买/发布的外观，保留原有动作及安全校验。

**第四步：回归。** 跑仓库现有测试、构建和 `docs/05-acceptance.md`；在 iOS 模拟器/真机捕获关键屏幕，按相同逻辑尺寸对照截图，检查大字号和减少动态效果。

每一步保持可运行的小改动；不要为 UI 升级框架、替换数据库、重建导航库或大量引入依赖。不要覆盖用户未提交的改动。

## 不允许的捷径

不要把 `preview.html` 嵌到 WebView 作为正式 UI；不要整体覆盖 App；不要使用 `seed()`、模拟 `pct()`、`setInterval` 演示进度或固定余额；不要因原型只有 TXT/Markdown 下载就删去正式 App 的 PDF/EPUB/DOCX 导出；不要把 sample 演示封面当用户文件封面；不要重画已经提供的人物或引入旧版人工校对页。

## 最终交付

说明修改文件、真实事件/服务如何接入、运行过的测试与结果，并附关键页面实际截图。逐项列出尚未验证的内容和因现有接口限制未完成的交互。没有实际调用/测试过的功能不得称为“验证通过”。本包是 UI 设计依据，不是业务规格重写授权。
